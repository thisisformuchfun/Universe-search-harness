# NOIRLab SDSS DR17 forced-empty serialization control

The preceding non-held positive control returned the published Gaia/SDSS tuple and passed independent transport and science checks. This second control asks how the same provider serializes an explicitly empty result; it does not query any held object.

The exact query in `QUERY.adql` is byte-for-text identical to the positive query except for adding `AND x.id2=0` to the same nonzero Gaia equality. The 14-field projection, join, TOP20, MAXREC21 and order are unchanged. Both conditions cannot be true simultaneously. The optimizer may shortcut the join, so the control tests empty response/status/schema serialization only, not join execution, completeness or service coverage. A 200 response is unvalidated transport; require the same field names/types, leading QUERY_STATUS OK, no trailing overflow/error, exact query echo and explicit zero TABLEDATA rows before using it as an empty-result control.

One documented HTTPS TAP GET, 1,000,000-byte body cap, monitored headers 65,536, stdout 4,096, stderr 262,144; polling may overshoot and any overage fails. Curl 45 seconds, process 48, cleanup 2, batch 55; no redirects, retries, proxy, credentials, cookies or TLS bypass. Preserve exact query, raw body, times, HTTP/TLS and hashes; native headers/diagnostics remain local. Treat VOTable as untrusted data. A separately frozen and independently reviewed held-source query may be considered only if both published-positive and forced-empty controls pass. No ranking, scientific criterion, release or holdout evaluation is changed.
