# Legacy Survey DR9 cutout: positive-control-only protocol

Purpose: check whether the documented public DR9-north FITS cutout endpoint delivers usable spatial coverage and a parseable WCS/inverse-variance product. This is preparatory to examining the scene near held Gaia DR3 1533365584518328576, where a low-S/N LAMOST spectrum has a one-detection PS1 object approximately 1.52 arcsec from the unpropagated Gaia position. This batch contains NO target-field request.

The one allowed GET is the survey's own northern example coordinate with a small region and subimage flag: https://www.legacysurvey.org/viewer/fits-cutout?ra=154.7709&dec=46.4537&layer=ls-dr9-north&pixscale=0.262&bands=grz&size=128&subimage&invvar . See https://www.legacysurvey.org/dr9/description/ and https://www.legacysurvey.org/svtips/ . No redirects, retries, credentials, cookies, proxy, custom CA or TLS bypass. Curl 8.4+ is required for streaming max-filesize handling. Limit 2097152 body bytes, 65536 headers, 4096 stdout, 262144 stderr; diagnostics/header polling can overshoot and any overshoot is a failure, not a hard bound. Curl limit 45 s; supervisor 48 s; 2 s owned-child cleanup; one 55 s batch deadline. Preserve native bytes, UTC timing, exact URL, TLS/HTTP/effective URL and SHA256; never print provider response or potentially sensitive headers/diagnostics.

The control only tests current service/format/coverage at its own position, not close-pair recovery, PSF, target coverage, detection completeness, masks, or source identity. Validate FITS integrity, actual HDUs and celestial WCS, target coordinate falling inside a finite, nonzero-weight region, and spatial signal without assuming a fixed number, size or order of HDUs. `subimage` avoids additional viewer resampling but the coadds are themselves resampled. Gaia DR2 astrometry and PS1 photometric calibration are shared; photons are distinct but calibration is not independent. Later target requests need a separate frozen continuation and review after the control is assessed. Even successful target images provide descriptive scene context only; the images cannot alone establish a physical companion, LAMOST fibre attribution, independent orbital RV, a black hole, or an exclusion limit. No scientific selection, ranking, release or holdout changes.

V2 lifecycle: under the common mutation lock, verify custody and session state, reject existing acquisition/science locks, create the acquisition lease and mark this session active. Pin the curl executable hash in the manifest. Persist a terminal RESULT while still holding the acquisition lease, including any in-memory owned PID and creation identity. If child exit is not confirmed, retain the lease with recovery information. Only after durable RESULT and confirmed exit may the mutation-locked coordinator clear this session and release its own lease; write a separate finish record. Never kill a process by stale PID. A preflight error or retained lock is not a target-data result.

V3 adds a custody and competing-lease/session-process recheck before shared finish; any drift leaves the acquisition lease intact. A missing FINISH after a durable RESULT is incomplete bookkeeping and requires local recovery before downstream interpretation, but no shared data or scarce resource is used after the confirmed child exit and lease release.

V4 distinguishes no child started, observed child exit, and unconfirmed/unknown exit; only the first two are safe for lease release. A no-child result does not claim an observed exit.

V5 checks the mutation-lease token immediately before each shared atomic replacement or acquisition-lease unlink. If ownership changed, it stops and preserves the new owner's lock.
