# NOIRLab SDSS DR17 published positive-control proposal

Question: does the actual provider's `specobj`–Gaia DR3 nearest-neighbor crossmatch return the published, non-held Gaia DR3 `1607896637338835712` with SDSS plate 7028, MJD 56449, fibre 220? [The miniJPAS paper's tables](https://wrap.warwick.ac.uk/id/eprint/170929/1/WRAP-The-miniJPAS-survey-white-dwarf-science-with-56-optical-filters-Tremblay-2022.pdf) link this tuple via object 2241–1747. The paper reports a white dwarf; it is a service/identity control, never a discovery. Presence in NOIRLab's clean view and nearest-neighbor relation is not assumed.

Prerequisite: the frozen schema-only response and both independent reviews, showing crossmatch id1 = specobjid, id2 = Gaia source_id, both BIGINT. At most one HTTPS GET of `QUERY.adql` to the documented NOIRLab TAP sync endpoint with REQUEST=doQuery, LANG=ADQL, FORMAT=votable and MAXREC=21. TOP 20 is a cap: overflow, 20 rows, truncated fields or ambiguity stop; a missing expected tuple is a failed control and says nothing about held sources. Preserve exact numeric identifiers as decimal strings; do not round via floating point. This query requests public observation metadata for the non-held control only; no spectrum pixels, RV, source from the original 14, ranking or policy change.

Transfer cap 1,000,000 bytes, monitored headers 65,536, stdout 4,096, stderr 262,144; polling may overshoot and any overage fails. Curl 45 seconds, process 48, cleanup 2, batch 55; no redirects, retries, proxy, credentials, cookies or TLS bypass. Preserve exact query, raw response, times, HTTP/TLS status and hashes. Treat XML as untrusted data and fail visibly for TAP ERROR/OVERFLOW, malformed or truncated VOTable, missing query status/echo, wrong types, duplicate or incomplete source/observation keys. An independently reviewed, same-join forced-empty control must pass before any separately frozen held-source query. The provider's clean view and 1.5-arcsec nearest-neighbor selection are not an exhaustive all-neighbor or epoch inventory; even a held-source match would need fibre, epoch and source-attribution validation.

The projection uses unique names for both join keys and includes both crossmatch coordinates and the spectrum fibre coordinates. No class, quality, redshift or primary filter is added beyond the provider view. The forced-empty control will repeat this projection/join/order with the contradictory x.id2=0 predicate.

HTTP_COMPLETE_VOTABLE_UNVALIDATED and exit 0 mean transport only, including for an empty body; the adapter does not parse TAP status or establish a positive-control match.
