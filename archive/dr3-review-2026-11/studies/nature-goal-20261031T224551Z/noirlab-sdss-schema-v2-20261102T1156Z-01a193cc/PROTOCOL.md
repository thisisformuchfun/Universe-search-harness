# NOIRLab SDSS DR17 schema-only probe

Hypothesis: the documented NOIRLab public TAP service exposes enough actual schema metadata to construct a later controlled SDSS DR17 optical-spectra/Gaia DR3 crossmatch query. This one request is only a schema inventory and contains no held IDs, source positions, spectral observations, or science sample selection. It adopts no scientific criterion, ranking, release policy or holdout methodology.

Use the exact query in `QUERY.adql` at the official `https://datalab.noirlab.edu/tap/sync`, `REQUEST=doQuery`, `LANG=ADQL`, `FORMAT=votable`, `MAXREC=101`. The two provider-described tables are `sdss_dr17.specobj` and its 1.5-arcsec nearest-neighbor Gaia DR3 crossmatch. The provider documents the [tables and TAP base](https://datalab.noirlab.edu/data/sdss) and [nearest-neighbor selection](https://datalab.noirlab.edu/data). Actual column names/types, current service availability and completeness are unverified. TOP 100 with a finite 18-name restriction makes a saturated/overflowed response invalid; missing fields are unknown until checked, not absent sources.

One HTTPS GET; 1,000,000-byte body cap, 65,536-byte monitored headers, 4,096-byte monitored stdout and 262,144-byte monitored stderr. Monitoring can overshoot; an overage fails. Curl 45 s, supervisor 48 s, owned-child cleanup 2 s and 55 s batch deadline. No retries, redirects, credentials, cookies, proxy or TLS bypass. Capture exact query/URL, raw response, time, status and checksums; headers/diagnostics stay local. Treat response XML as untrusted data. Stop on HTTP failure, TAP error, malformed VOTable, overflow, truncation, cap, or ambiguous schema. Successful schema alone never establishes a source match, missing spectrum, independent RV epoch or discovery. A separate positive-control and forced-empty protocol must precede any held-source query.

HTTP_COMPLETE_VOTABLE_UNVALIDATED and process exit 0 mean transport only, even for an empty body. Independently inspect TAP QUERY_STATUS including OVERFLOW/ERROR, XML schema, row completeness, types and truncation before proposing any held-source query.
